# Release v1.3.1

## What's New (App Store)

```
- Fixed an issue where an alarm edited after reinstalling the app could miss its next time
- Fixed an issue where removing a time from an alarm could leave the old time still ringing
- Fixed an issue where a ringing or snoozed alarm could go silent when the app was reopened
- Fixed an issue where completion history recorded the wrong date for an alarm
- Scheduling problems are now reported instead of failing silently
```

## Promotional Text

Unchanged from 1.3.0.

## Internal Release Notes

**Version:** 1.3.1 (build 1)
**Platform:** iOS only
**Branch:** sprint-surfaces (BUG-08 to BUG-13), fast-forwarded to main

### Bug Fixes
- **BUG-08** `register()` no longer drops the next occurrence when AlarmKit still holds a stale `.alerting` registration; only `.countdown` (snooze) is protected.
- **BUG-10** Removed time slots are cancelled through the registration ID map instead of being orphaned.
- **BUG-11** `rescheduleAllAlarms` skips alarms that are ringing, missed or snoozed, so a cold launch does not silence them. The release drive showed the AlarmKit snapshot is empty one second into a cold launch, so the guard now also keys off the model (`nextFireDate <= now`).
- **BUG-12** Completion logs record the occurrence the user acted on, not the recomputed next date.
- **BUG-13** `try?` around save/schedule replaced with `recordError`; scheduling throws `notAuthorized` when AlarmKit is not authorized.

### Not in this build
- Android changes on this branch (ANDROID-05, ANDROID-06, ANDROID-07) ship with the next Android release.
- CI-only changes (INFRA-03) have no user-facing effect.
